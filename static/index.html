1. 중복 요청 방어 (Distributed Nonce & Idempotency)

같은 쓰기(Write) 요청이 두 노드에 동시 인입될 때, 정확히 하나만 승인(Race Condition 방어)되는지 확인합니다.

[원리] 예상 결과 및 원리 보기 (Redis 정상 vs 장애)
• Redis 정상 시: 분산 원자적 소진으로 1개 통과(200 OK) / 1개 차단(401 Replay Detected).
• Redis 장애 시: 분산 락/조율이 불가능하므로 이중 결제·데이터 오염을 막기 위해 양쪽 노드 모두 503(Fail-Closed)으로 안전 차단됩니다. (보안 안전 장치 정상 동작)

2. 대규모 트래픽 방어 (Sliding-Window Rate Limiter)

짧은 시간에 50건의 연속 요청을 보내 시스템이 초과 트래픽을 즉각 차단(429)하여 백엔드를 보호하는지 봅니다.

[원리] 예상 결과 및 원리 보기
• Redis 정상 시: 전역 슬라이딩 윈도우(10초당 50개)를 초과하는 트래픽을 즉시 429로 방어합니다.
• Redis 장애 시: 각 게이트웨이가 노드별 로컬 인메모리 슬라이딩 윈도우(10초당 15개)로 자동 폴백하여 노드 다운을 방어합니다.

6. Same-key Burst (Single-flight Test)

동일한 키로 동시에 여러 요청이 쏟아질 때(Thundering Herd), 백엔드 DB 조회를 1회로 병합하고 부하를 얼마나 줄이는지 확인합니다.

[원리] 예상 결과 및 원리 보기
동작 원리 (Single-Flight 병합):
동일한 리소스(사용자/정책)에 대해 50개의 요청이 캐시 미스 상태에서 동시에 도달하면, 최초 요청(Leader)만 실제 DB를 조회하고 나머지 49개 요청(Followers)은 메모리에서 대기(In-flight Coalescing)하다가 Leader의 응답 결과를 그대로 공유받습니다.
→ 50번 발생할 수 있는 DB 쿼리가 단 1번으로 압축되어 DB 부하를 약 98% 절감합니다.

4. 백엔드 장애 격리 (DB Outage & Circuit Breaker)

백엔드 DB를 멈춰서 모든 게이트웨이가 연쇄 장애(Cascading Failure)를 막기 위해 서킷 브레이커(Open)를 작동시키는지 봅니다.

5. 공유 캐시 장애 대응 (Redis Outage & Degraded Mode)

Redis Normal

중앙 캐시(Redis)가 다운되었을 때 시스템이 가용성과 보안 원칙에 따라 어떻게 차등 대응(Graceful Degradation)하는지 확인합니다.

[원리] Redis 중단 시 동작 매트릭스 (Availability vs Consistency)
[정상] L1 로컬 인메모리 캐시

이미 노드 메모리에 적재된 정책 데이터는 Redis 없이 1ms 미만 초고속 응답

[정상] 로컬 슬라이딩 유량 제어

노드별 독립 메모리 카운터로 자동 폴백 (15 req/10s 초과 시 429 차단 방어)

[정상] Policy DB 직접 폴백 및 서킷

L2 캐시 우회 후 DB 직접 조회 및 L1 적재 (서킷 브레이커 독립 감시)

[정상] 단일 비행 (Single-Flight)

로컬 Future 기반 동일 키 50개 요청을 1회 DB 쿼리로 병합

[차단] Fail-Closed 분산 Nonce 중복 방어

분산 락 부재 시 이중 결제/데이터 오염 방지를 위해 503 즉시 차단 (정상 동작)

[정합성] 통계 불변식 100% 일치

503 차단 트래픽이 redis_outage_blocked에 집계되어 관측 무결성 유지

3. 네트워크 단절 및 복구 (Partition & PEL Catch-up)

Node-B의 통신을 끊어 분립시키고, 복구될 때 Redis Streams PEL(Pending Entries List)을 전량 동기화(Catch-up)하는지 봅니다.

[원리] 예상 결과 및 원리 보기
단절 상태에서는 Node-B가 외부와 완전히 고립되므로 Split-Brain이 방지됩니다. 복구 시 즉시 Pending Entries List(PEL)의 미처리 이벤트를 전량 드레인하여 데이터 정합성을 일치시킵니다.

7. 캐시 무효화 전파 (Pub/Sub Stream Invalidation)

정책 데이터가 변경되었을 때 Redis Streams를 통해 모든 분산 게이트웨이의 L1 로컬 캐시를 실시간으로 즉시 무효화(삭제)합니다.

[원리] 예상 결과 및 원리 보기
특정 노드에서 정책 변경이 발생하면 Redis Streams(invalidation_stream)에 이벤트를 발행합니다. 모든 활성 게이트웨이 노드가 실시간 리스너를 통해 이벤트를 수신하고 자신의 L1 메모리 캐시를 즉각 삭제하여 데이터 정합성을 유지합니다.
